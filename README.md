# Bluetooth Audio для магнітоли

**Проєкт:** передавач звуку з магнітоли на Bluetooth-навушники або колонки з вибором пристрою на сенсорному дисплеї **FSA506 480×272**.

## Архітектура: один мікроконтролер ESP32-S31

> **Проєкт орієнтований на один ESP32-S31, не на два ESP32.**
> ESP32-S3 для цієї задачі **не підходить сам по собі**: у нього немає Bluetooth Classic / A2DP Source. ESP32-S31 підтримує Classic A2DP Source, I²S та паралельний LCD. Потрібні лише периферійні компоненти для вводу аналогового аудіо та дисплей.

```text
                         один ESP32-S31
                        ┌─────────────────────┐
Магнітола LINE OUT L/R ──> Стерео I²S ADC ──> I²S RX
                        │  Bluetooth Classic  │ ──> BT-навушники/колонка
Touch 4-wire ────────────>  GPIO + ADC         │
FSA506 480×272 <──────────  8-bit 8080 LCD    │
                        └─────────────────────┘
```

### Чому ESP32-S31

- **Bluetooth Classic A2DP Source** — пошук, pairing і передавання SBC-аудіо у звичайні Bluetooth-наушники/колонки.
- Bluetooth LE 5.4 також є, але для звичайних A2DP-пристроїв він не використовується.
- Підтримує **паралельний LCD** та велику кількість GPIO.
- **I²S** для зовнішнього стерео ADC і обробки потоку PCM.
- Наявні ADC-входи для чотирипровідної резистивної сенсорної панелі.

**Важливо (листопад 2026):** підтримка ESP32-S31 в ESP-IDF розвивається у **master (preview)**, а не в перевіреному нами ESP-IDF 5.5.x. Код, конфігурації GPIO і CMake з ESP32-S3 не є бінарно сумісними з S31. Збірка та робота на обладнанні наразі **не перевірені**.

## Перенесення робочого FSA506 і Touch

Базовий референс: [Silvus Configurator, hw/esp32s3-fsa506](https://github.com/garik816/silvus-configurator/tree/hw/esp32s3-fsa506/main).

**Переносимо алгоритми, а не GPIO один-в-один:**
- регістрову ініціалізацію FSA506, 480×272 таймінги, GRAM-window, RGB565;
- построчну передачу кадрового буфера та рендеринг;
- фільтрацію торкань, 5-точкову калібровку й збереження до NVS;
- користувацький інтерфейс адаптуємо до списку Bluetooth-пристроїв.

**Обов’язкові зміни для ESP32-S31:**
1. Замінити ESP32-S3 `esp_lcd_new_i80_bus()` на підтримуваний у S31 `esp_lcd_new_panel_io_parl()` (8-bit I80).
2. Нова таблиця GPIO: попередні S3 GPIO1/2/7/8 **не є ADC1 на S31**. За документацією S31 ADC1 — GPIO42…49, вони підходять для аналізу сигналів Touch після перевірки режиму ADC.
3. Не використовувати нові GPIO Touch одночасно для шини FSA506 чи I²S.
4. Перевірити підтримку Touch через ADC API S31 і повторно відкалібрувати панель.
5. Окремо валідовувати Bluetooth та вивід зображення, потім їх одночасну роботу.

**Підключення FSA506 на S3 не можна фізично повторювати без переназначення:** старі GPIO 14…47 були обрані для іншого чипа. Точна схема S31 визначається після вибору плати, на якій доступні потрібні контакти.

## Аудіовхід

Потрібний **стерео АЦП з цифровим виходом I²S** (наприклад, плата на PCM1808) між *лінійним* аудіовиходом магнітоли і ESP32-S31. ADC — **не другий мікроконтролер**.

- Джерело: LINE OUT L/R (не BTL speaker output).
- Потік: стерео PCM, типовий тестовий режим 44,1 кГц.
- Цифрові сигнали: BCLK, WS, DATA, за необхідності MCLK; живлення і рівні згідно з документацією конкретного АЦП.
- Для виходів підсилювача/динаміків потрібне належне speaker-to-line узгодження; **не підключати їх напряму** до мікроконтролера або ADC.

## Функції інтерфейсу

1. **SCAN** — пошук Bluetooth Classic пристроїв з A2DP Sink.
2. Список із назвою, MAC, рівнем сигналу (коли доступний).
3. Натискання на пристрій — **CONNECT** / **DISCONNECT**.
4. Статус **SEARCHING / CONNECTING / CONNECTED / STREAMING / ERROR**.
5. Збереження останнього пристрою у NVS, можливість авто-підключення.
6. Окрема сторінка калібрування Touch і журнал помилок.

## План реалізації

1. Створити проєкт ESP-IDF `idf.py set-target esp32s31` із актуальної гілки master ESP-IDF.
2. Перенести FSA506 register init і рендеринг на 8-бітну PARL LCD шину.
3. Перенести Touch у новий драйвер GPIO + ADC1 S31, зробити калібровку.
4. Реалізувати GAP discovery / bonding / A2DP Source за офіційним прикладом ESP-IDF.
5. Реалізувати I²S RX для ADC, буферизацію стерео PCM, feeding A2DP callback.
6. Відтестувати звук, паузи, перепідключення, dropout, холодний запуск і одночасне оновлення LCD.

**Поточний стан репозиторію:** документовано обрану одночипову архітектуру. Прошивки та апаратне підтвердження ще не створено. До вибору фізичної плати ESP32-S31 і ADC не слід фіксувати GPIO як остаточні.

## Запасний варіант

Якщо ESP32-S31 поки недоступний, **один класичний ESP32-WROOM-32E** також може виконувати A2DP Source і приймати I²S audio, але реалізація 8-бітного FSA506 потребуватиме нестандартного I²S/parallel драйвера та обережного розподілу GPIO; це менш бажаний напрямок для дисплея 480×272.

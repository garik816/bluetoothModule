# BluetoothModule — Raspberry Pi Pico 2 (RP2350)

**Гілка:** `hw/rp2350-pico2`. Окремий порт проєкту під звичайну **Raspberry Pi Pico 2 (RP2350A)**. Прошивка RP2350 розміщена у каталозі `rp2350-pico2/` і збирається Pico SDK 2.3.1.

## Схема пристрою

```
Магнітола LINE OUT L / R --аналогове аудіо--> KCX_BT_EMITTER v1.7
                                             |
                                             | Bluetooth A2DP Source
                                             v
                                      Навушники / колонка

Raspberry Pi Pico 2 (RP2350A)
    |  UART0 115200 (через узгодження рівнів)
    +------------------------------------------ KCX_BT_EMITTER v1.7
    |
    |  PIO0 + DMA, 8-bit 8080
    +------------------------------------------ FSA506 480x272
    |
    |  GP26 / ADC0, GP27 / ADC1, GP20 / GP21
    +------------------------------------------ 4-wire резистивний Touch
```

Pico 2 **не виконує кодування Bluetooth-аудіо**: звук іде безпосередньо до KCX, а RP2350 керує пошуком/сполученням та екраном.

## Тимчасовий режим діагностики Touch

У поточній прошивці `MODULE_KCX_ENABLED=OFF` за замовчуванням. **KCX повністю вимкнено**: UART0/MODE не ініціалізуються, жодні AT-команди не відправляються, Bluetooth не опитується. Це дозволяє перевіряти дисплей та 4-провідний сенсор без підключеного KCX.

На дисплеї заголовок **`universal bluetooth module v.<version>`**. Версія генерується автоматично **при кожній збірці**, включно з повторним `cmake --build` без змін коду. У CI використовується номер `GITHUB_RUN_NUMBER` (наприклад, `0.2.14`), локально — лічильник у `build-pico2/generated/build_version.count`.

### USB-діагностика (COM-порт Pico 2)

```powershell
python -m serial.tools.miniterm COM22 115200
```

В журналі: `[BOOT]`, `[TOUCH DOWN]`, `[TOUCH RAW]`, `[TOUCH UP]`, `[CAL]`, `[CAL ERROR]`, `[CAL STORAGE]`, `[HEARTBEAT]`. Стан ADC виводиться щонайменше кожні 200 мс під час тривалого дотику; 5 точок калібрування перевіряються окремо із поясненням відмови.

Команди в USB-терміналі: `p` — одинична перевірка електродів/ADC, `c` — калібрувати заново, `d` — детальний RAW-лог ON/OFF, `h` — допомога, `v` — версія.

**Вмикання KCX пізніше:** `cmake -S rp2350-pico2 -B build-pico2 -DMODULE_KCX_ENABLED=ON`, потім `cmake --build build-pico2`. GPIO залишаються як у таблиці нижче.

**Важливі уточнення щодо роз'єму:**

- На самому модулі підписані **TOUCH1, TOUCH3, TOUCH2, TOUCH4** саме в порядку контактів **30, 31, 32, 33**. Внутрішні назви `X1, X2, Y1, Y2` у `src/pins.h` і `src/touch.c` відповідають наведеній таблиці; вони не означають порядок написів на шлейфі.
- Пін **34 — DB24** записаний **точно як у вашій таблиці**: не припускаємо, що це DB20, DB23 або додатковий сигнал. Контакти DB08–DB19 та DB24 не потрібні для обраного 8-бітного режиму.
Для роботи з **DB00–DB07** дисплей повинен підтримувати обраний режим **8-bit 8080, RGB565**. Перевірте положення апаратних перемичок та режим контролера FSA506; самої наявності DB00–DB07 на роз'ємі недостатньо.
- Вхід **/RD** прошивка ініціалізує як HIGH, читання з FSA506 не виконується. **/RESET** у наданому 40-контактному списку не позначений: прошивка розрахована на штатний апаратний reset при подачі живлення.
Позначення **VCC** саме по собі не підтверджує допустиму напругу. Перевірте електричну схему та вимоги до живлення конкретної плати FSA506 перед подачею напруги. Не живіть дисплей або підсвічування від `3V3(OUT)` Pico 2 без перевірки струму.
- Всі **GND** з роз'єму слід з'єднати із загальною землею згідно зі схемою модуля. Для Pico 2 можна використати будь-який вивід `GND` (наприклад, фізичні контакти 3, 8, 13, 18, 23, 28, 33 або 38).
- GPIO `GP0…GP28` на Pico 2 — **3,3 В логіка**, не подавати 5 В безпосередньо.

## Інші з'єднання Pico 2 ↔ KCX_BT_EMITTER v1.7

| KCX сигнал | Pico 2 GPIO | Фізичний контакт Pico 2 | Примітка |
|---|---|---:|---|
| KCX RX | GP0 / UART0 TX | 1 | Від Pico до KCX, через узгодження логічних рівнів |
| KCX TX | GP1 / UART0 RX | 2 | Від KCX до Pico, **через перетворювач 5→3,3 В**, якщо KCX TX = 5 В |
| KCX MODE | GP15 | 20 | HIGH = режим EMITTER/TX, через узгодження за потреби |
| KCX LINK | — | — | Не використовується; статус читається командою `AT+STATUS?` |
| KCX VCC | — | — | Живлення за документацією конкретної плати KCX (часто 5 В) |
| KCX GND | GND | — | Спільна цифрова земля |
| KCX LINE IN L/R | — | — | Аналоговий лінійний стереовихід магнітоли |

Для перевірки проводки: контакт **10 дисплея DB00 → GP2 (контакт 4 Pico 2)**, контакт **17 дисплея DB07 → GP9 (контакт 12 Pico 2)**. Не плутайте номер контакту роз'єму дисплея з номером фізичного контакту Pico 2.

Цей проєкт використовує 8-бітний інтерфейс 8080, RGB565, параметри FSA506 480×272 (H525/V286) та наведене вище підключення. Значення GPIO визначені у `src/pins.h`. Робота на фізичній платі ще потребує перевірки.

**Безпека:** GPIO RP2350 не є 5-вольт-толерантними. UART/MODE KCX потрібно узгоджувати за напругами, бо ревізії KCX v1.7 можуть мати 5V-логіку. Не подавати на Pico 2 живлення 5 В через GPIO, не під’єднувати вихід автомобільного підсилювача до KCX LINE L/R (потрібен справжній LINE OUT або BTL speaker-level-to-line адаптер). Підсвічування FSA506 і `/RESET` не керуються GPIO Pico 2; для них необхідні штатні кола живлення та апаратного скидання.

## Збірка Pico SDK 2.3.1

Встановіть **Pico SDK 2.3.1**, ARM GNU Toolchain, CMake та Ninja. Це C/C++ проєкт, **без ESP-IDF / Arduino / PlatformIO**.

PowerShell 7:
```powershell
git clone -b hw/rp2350-pico2 https://github.com/garik816/bluetoothModule.git
cd bluetoothModule
$env:PICO_SDK_PATH = "C:\pico\pico-sdk"
cmake -S rp2350-pico2 -B build-pico2 -G Ninja -DPICO_BOARD=pico2
cmake --build build-pico2 --parallel
```

**UF2:** `build-pico2/bluetooth_module_pico2.uf2`. На Pico 2 утримуйте **BOOTSEL** при підключенні USB; скопіюйте UF2 на диск **RP2350**. Через USB CDC прошивка виводить журнал команд `KCX TX`/`KCX RX`, якщо комп’ютер відкриває CDC-порт.

CI: [GitHub Actions — RP2350 Pico 2 UF2](https://github.com/garik816/bluetoothModule/actions/workflows/pico2.yml), артефакт `bluetoothModule-RP2350-Pico2-UF2`.

## Робота з пристроєм

1. Переведіть Bluetooth-навушники в режим сполучення, KCX — у режим EMITTER.
2. При першому запуску натисніть п’ять червоних хрестиків Touch: лівий верхній, правий верхній, правий нижній, лівий нижній, центр. Параметри зберігаються у **останньому 4 КБ секторі Flash**. Збірка повинна вміщуватися без перетину цього сектора.
3. **ПОШУК** — `AT+PAIR`; список `MacAdd:` + `Name:`, 4 елементи на сторінку.
4. Виберіть рядок і натисніть **ПІДКЛ.**: прошивка видаляє попередні адреси з пам’яті KCX (`AT+DELVMLINK`), зберігає вибрану (`AT+ADDLINKADD=<MAC>`) і запускає сполучення.
5. **ВІДКЛ.** надсилає `AT+DISCON`, **ДАЛІ** перемикає сторінку, **CAL** у шапці повторює калібрування.

**Обмеження KCX v1.7:** у протестованих сторонніми авторами ревізіях `AT+SCAN` не працює надійно. Заміна на `AT+PAIR` не гарантує суто пасивного сканування: модуль **може автоматично приєднатися** до першого пристрою. Успішність пошуку та обмеження підключення одним MAC необхідно підтвердити на реальному KCX.

## Примітки щодо реалізації

- LCD 8080: PIO0 SM0, 8 GPIO data + GP10 /WR side-set, DMA для послідовності байтів, GRAM смугами по 8 рядків, без повного framebuffer.
- Touch: ADC0 GP26 та ADC1 GP27, драйвінг X/Y на двох цифрових GPIO, опитування 30 мс.
- Калібрування: останній 4 КБ сектор зовнішньої Flash, CRC32, одноразовий запис після калібрування. Не запускати друге ядро під час операцій із Flash.
- UART: приймання в кільцевий буфер 4096 байтів із IRQ, щоб не губити відповіді KCX під час перемальовування LCD.
- Текст: український інтерфейс, 8×12 піксельний шрифт із Unicode Cyrillic; гліфи на основі [512_8_sans, public domain](https://github.com/alexfru/512_8).
- Аудіо: виключно лінійний стереовхід KCX, жодних аудіоперетворень у RP2350.

**Статус:** автоматична збірка UF2 на Pico SDK 2.3.1 пройшла успішно (GitHub Actions, run 42614009894); фізичні вимірювання та роботу з дисплеєм/Touch/KCX ще не підтверджено. Зокрема перевірити byte order IM4, /WR PIO timing, реальні рівні KCX UART, зберігання калібровки, затримку аудіо.
